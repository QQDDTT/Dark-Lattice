ソフトウェアエンジニアリングにおける大規模言語モデル（LLM）とマルチエージェント（Multi-Agent）協調の浸透に伴い、私たちは新たな開発時代を迎えている。すなわち、Agent が人間に代わって膨大な UI コードを生成する時代である。しかし、既存の自動コード生成の多くは「ジグソーパズル」のような機械的な組み合わせに陥りがちであり、生成されるインターフェースはデザイン性に欠け、余白の扱いも粗く、インタラクションの意図に応じた微細な状態遷移を実現することが困難であった。

**Gestalt Resonator (完形共鳴器)** は、まさにこの課題を解決するために誕生した。「要件定義（Requirement）」と「高精度かつ優れたユーザー体験を提供するコード（High-Fidelity Code）」を繋ぐ架け橋として、ゲシュタルト心理学（Gestalt Psychology）、デザイン構成理論、およびソフトウェアエンジニアリングモデルをシステムレベルでマッピングしたクロスプラットフォーム画面デザイン合成・翻訳システムであり、Agent 協調のための「設計ミドルウェア」となることを目指している。

## コア理念：ゲシュタルト原則と計算論的思考のシステム同調

従来の UI 自動生成は、インターフェースを単に独立した DIV と CSS プロパティの集合として扱っていた。これに対し、Gestalt Resonator は視覚的知覚とソフトウェアエンジニアリングを深く同調させている。

1. **全体は部分の総和に勝る (The whole is other than the sum of the parts)**
   UI デザインにおける硬質で細切れの境界線は、しばしば視覚的なノイズを引き起こす。Gestalt Resonator は、宣言的デザインスキーマ（DDSL）に**接近性グループ (Proximity Groups)** と**骨格グリッド (Grid Skeleton)** という概念を導入した。数式に基づいてグリッドの感覚やソフトな余白を定義することで、Client Agent がコードを翻訳する際、物理的な境界線ではなく視覚的な接近度合いに依存するように誘導する。これにより、ユーザーの「閉合性 (Closure)」と「接近性 (Proximity)」の知覚を呼び起こす。

2. **形は機能に従い、技術は芸術と融合する**
   システムは、**HSL (Hue, Saturation, Lightness) 色空間** に基づくデザイントークンを全面的に導入し、独自のアルゴリズムを通じて**視覚的重力 (Visual Gravity)** の分布を制御する。これにより、調和の取れた配色が保証されるだけでなく、テーマの切り替えや明暗の変化に対しても、極めて高い保守性とグローバルなデザインの一貫性が保たれる。

3. **「共同運命」 (Common Fate) の物理アニメーション**
   ゲシュタルト心理学において、同じ方向に動く要素は一つのグループとして知覚される。我々は「共同運命」の物理モーションモデルを定義し、システムバックエンドの様々な制御状態（要求タイムアウト、データ異常、編集モードへの移行など）を、インターフェース上の関連コンポーネントが協調して動作するマイクロインタラクション（同期したジッター、連動したスライドイン、フェードなど）に変換する。これにより、インタラクション状態の遷移が自然で直感的なものとなる。

## 主要技術：DDSL 契約パッケージとダブルモード翻訳機構

Gestalt Resonator が出力するインターフェース設計は、単なる HTML コードの断片ではなく、Client Agent に提供される完全な**開発契約パッケージ (Design Contract Package)** である。

### 1. 契約パッケージの構造 (Contract Package Structure)
* **DDSL セマンティクス JSON (`layout.ddsl.json`)**：標準 Schema に基づいて設計され、Agent 向けのコード生成制約や設計根拠アノテーション（`_agent_guidelines`）が埋め込まれており、レイアウトの意図を明確に伝える。
* **配色およびレイアウトトークン (`design_tokens.css`)**：グローバルな CSS カスタムプロパティ（CSS 変数）として切り離され、システム全体の美学的品質を担保する。
* **Agent 翻訳ガイドライン (`TRANSPILER_RULES.md`)**：CLI によって動的に生成される。Client Agent はこのファイルを自身の System Prompt に直接注入することで、レイアウトツリーに対する最適な解析メンタルモデルとコーディング制約を獲得できる。
* **QA チェックリスト (`design_qa_checklist.json`)**：インタラクション状態マシンのエンドツーエンド（E2E）アサーションケースを定義する。Client Agent はこのリストに基づいて自動回帰テストを実行でき、「UI の表面的な正常化」（コードは動作するがレイアウトが崩れている、または状態マシンのロジックが誤っている現象）を完全に防止する。

### 2. 通常ワークフローのダブルモード (Dual-Mode regular workflow)
システムは、自動化パイプラインや対話型 Agent の推論シナリオに適応するため、2つの実行モードをサポートしている。
* **本番モード (Production Mode)**：入力された要件定義が解析された後、システムは**内蔵された API トークン**を使用して **Gemini API** を呼び出し、特定のビジネスコンテキストに合致したリアルなデザインテキストを自動生成し、DDSL やトークンと統合して納品する。
* **推論モード (Reasoning Mode)**：内蔵 API トークンの不必要な消費を抑えるため、システムは**外部 API へのネットワークリクエストを一切送信しない**。代わりに、インターフェースの骨格と意図の記述を含む `ReasoningContext` をエクスポートし、受け手側（ローカルの Client Agent など）が自身の計算資源とモデルを使用してローカルで自律的にコピーライティングの推論と最終的なコード生成を実行できるようにする。

### 3. 素材の蓄積と特徴監査 (Asset Accumulation & Feature Audit)
順方向の合成だけでなく、システムは**素材蓄積ワークフロー**もサポートしている。既存の優れた HTML/CSS や Figma デザインを DDSL フラグメントに逆解析し、`AssetFeatureAnalyzer` を使用してゲシュタルト監査（高コントラストカードに自動的に `FigureGround` 原則の特徴タグを付与するなど）および「美学的な指紋（Aesthetic Fingerprint）の抽出」を行い、将来の精密なマッチングのために高品質な素材を蓄積する。

## 段階的な技術マイルストーン

現在、Gestalt Resonator は強固な基盤エンジニアリングを構築しており、以下のマイルストーンを完了している。
- **契約 Schema の固化**：Agent 向けの DDSL コア Schema 契約設計 (`ddsl.schema.json`) を完了。
- **DDD 境界コンテキストの定義**：ドメイン駆動設計 (DDD) の思想に厳格に従い、要件パラメータ、素材管理、DDSL 合成、およびデリバリーの4つの主要な境界コンテキストのドメインモデルを分割・定義。
- **エンジニアリングスケルトンの構築**：Cargo プロジェクトおよびコア依存関係の初期化、ならびに開発用コンテナ環境（`.devcontainer`）の構築を完了。

## 今後のロードマップ

次の開発サイクルでは、以下の技術的ブレイクスルーに焦点を当てる。
1. **逆シリアル化パーサー**：DDSL 契約ファイルから Rust エンティティへの高速な解析および逆シリアル化の実装。
2. **CLI ドライバーの強化**：`gestalt-resonator` コマンドラインツールの `generate` および `get-context` コマンドの具体的なロジックを改良し、stdio を通じたストリーミング JSON-RPC インタラクションをサポート。
3. **統合検証**：マルチ Agent が「本番／推論」のダブルモード下で協調して翻訳を行うプロセスを再現する、エンドツーエンドの統合テストケースの構築。
