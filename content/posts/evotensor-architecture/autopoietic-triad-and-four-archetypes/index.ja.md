# 全域アーキテクチャの大統一：Evopoiesis 自己創出進化、4大直交分類体系とデータ・計算力・エッジ三軌分離の鉄則

> **統括中枢**：Evopoiesis（自己創出進化プラットフォーム）＆ Workspace-Hub（ワークスペースナビゲーション中枢）  
> **変革マイルストーン**：「普通（Ordinary）」カテゴリの撤廃、全23プロジェクトの4大直交カテゴリ体系の確立、三軌分離の鉄則およびSPEC-17全域UI端末適応強制ベースラインの実装  
> **基本理念**：*「システムの誕生は規則の礎に始まり、システムの進化は構造の脱皮に現れる。」*

---

## 1. エントロピー危機：なぜマルチプロジェクト環境は「規律の漂流」に陥るのか？

開発ワークスペースが数個の実験的リポジトリから**20以上の専門領域プロジェクト**（米国株・FXクオンツ取引、Kaggle強化学習、ゼロトラスト透過ゲートウェイ、ESP32 IoTクラウドビルド、法務・税務ガバナンス智庫、テーブルトップH5ゲーム群、マルチエージェント理論中枢）へと拡大すると、強固なトップダウンのメタアーキテクチャがなければ必然的に3つのエントロピー危機が発生します：

1. **分類境界の崩壊と「普通（Ordinary）」カテゴリのゴミ箱化**：
   初期の5分類体系には「普通／汎用システム（Ordinary / General）」という受け皿カテゴリが存在していました。しかし、ゼロ攻撃面セキュリティゲートウェイ（`Aegis-Gate`、`SynapseGate`）、AIリアクターOS（`Aura`）、3D技術ブログ（`Dark-Lattice`）、そして初期のC#/Java教育用ソリューションがすべてこのカテゴリに混在した結果、リポジトリの公開設定（`PRIVATE` vs `PUBLIC`）やクラウドパイプライン要件が真っ向から対立し、例外規定の継ぎ接ぎを余儀なくされていました。
2. **ホスト環境のランタイム汚染とクラウド常駐コストの暴走**：
   軽量な開発ホスト端末（Surface Pro 9）にPython、Node.js、Rust、Java、.NETなどのランタイムを無秩序に導入すれば、数十GBの `.venv` や `node_modules` がストレージを圧迫します。さらに、GCP上にCloud RunやGCE常駐インスタンスが放置されれば、アイドル課金が際限なく発生します。
3. **端末間のUI体験の分断**：
   デスクトップ大画面のみを想定して設計された管理コンソールは、スマートフォン縦画面やタブレットでの緊急巡回時に横スクロールのはみ出し、タッチ領域の不足、ノッチやジェスチャーバーによる操作系の遮蔽といった致命的な欠陥を露呈しました。

これらの構造的課題を根絶するため、**`Evopoiesis`** 主導による全域アーキテクチャの大統一改革を断行しました。

## 2. 「普通」カテゴリの完全撤廃：4大直交プロジェクト分類体系の確立

曖昧な「普通」カテゴリを完全に廃止し、既存プロジェクトの統廃合と再配置を行い、例外規定ゼロの**4大直交標準カテゴリ（全23アクティブプロジェクト）**へと収束させました：

| カテゴリ名 | 識別子 | リポジトリ公開性 | `.ops` パイプライン | 中核責務とアーキテクチャ契約 | 代表プロジェクト |
| :--- | :---: | :---: | :---: | :--- | :--- |
| **主控** | `Console` | **PRIVATE** | **`.ops` 不要** | デスクトップ統合コンソール、次世代自律型IDE工房、ローカルコンテナ計算力と階層型モデルルーティング基盤 | `Workspace-Hub`、`Evo-Studio` |
| **基礎** | `Foundation` | **PRIVATE** | **`.ops` 不要** | 全域基礎理論、セキュリティ監査、UI/美術トークン、クラウド計算力編成とメタアーキテクチャ中枢；**ホストグローバルへの `SKILL` 配信を担う** | `Evopoiesis`、`Harness-Forge`、`Aegis-Sec`、`Momus-Audit` 等（全8プロジェクト） |
| **プラットフォーム** | `Platform` | **PRIVATE**<br>*(公開 `*-UI` 副リポジトリ付)* | **標準3入口必須** | エンドユーザー向け製品、セキュリティ透過ゲートウェイ、対話型演習母機；ソースは非公開、静的UIは独立 `*-UI` 公開リポジトリから配信 | `Quant-FMP`、`Quant-FX`、`Aegis-Gate`、`SynapseGate`、`Syntax-Lab`、`Nex-Micro` 等（全12プラットフォーム） |
| **展示ポータル** | `Showcase` | **PUBLIC** | オンデマンド検証 | 純静的技術ブログおよび最先端研究レポート展示ポータル；メインリポジトリを公開しGitHub Actionsで自動配信 | `Dark-Lattice` |

## 3. 物理的基盤：データ・計算力・エッジ配信の「三軌分離」鉄則

`Evopoiesis` と `Aether-Ops` の共同統治のもと、全ワークスペースで **ホストゼロランタイム（Local Zero-Runtime）** と **三軌分離（Storage, Compute & Hosting Triad）** を徹底しています：

1. **ホスト環境の完全純粋性（Zero Local Runtime）**：
   開発ホストへの外部言語ランタイムやパッケージマネージャの導入を一切禁止し、Windows標準の **PowerShell**、**BAT/CMD**、および標準 `.NET Framework csc.exe` でコンパイルされた61.5KBの超軽量ネイティブデスクトップ中枢 `Workspace-Hub` のみで全運用を完結させます。
2. **第1の軌道・Google Driveデータ中枢とデータ防壁**：
   全プロジェクトのソースコード、設計書、Parquetデータレイク、メディア資産をGoogle Driveに一元集約し、`.gitignore` の **Evopoiesis Data Barrier** によって5MB超のバイナリや業務データのGit混入を厳格に遮断します。
3. **第2の軌道・GCP一時的弾性計算力（`Destroy-on-Exit` / 常駐サービス厳禁）**：
   **GCP上での長期常駐サービス（Cloud Run、常駐GCE VM、GKE）のデプロイを絶対禁止**とします。GCPはコードビルド（Cloud Build）、モデル学習、高負荷バッチ処理のみに限定し、60%〜91%割引の **Spot（プリエンプティブル）インスタンス** を強制採用。Google内部バックボーン経由（通信費$0）でGoogle Driveに結果を書き戻した直後にインスタンスとブートディスクを自動破棄し、非稼働時のクラウド費用を **`$0.00`** に保ちます。
4. **第3の軌道・主従リポジトリ分離とゼロコストエッジ配信**：
   すべてのプラットフォームは非公開メインリポジトリ（`QQDDTT/<Project>`）でソースコードを保護し、サニタイズされた静的フロントエンドのみを独立公開副リポジトリ（`QQDDTT/<Project>-UI`）へ同期してGitHub Pages + Cloudflare CDN（`*.evotensor.dev`）から配信します。

## 4. SPEC-17：全域UI端末適応必須規約

フロントエンドのマルチデバイス体験を保証するため、**SPEC-17** によりUI端末適応を全非基礎プロジェクトの必須要件へ昇格させました：
- **対象端末形態の明示**：各プロジェクトの `AGENTS.md` にて対象ビューポート（PCワイド画面 $\ge 1024\text{px}$、タブレット $768\text{px}\sim 1023\text{px}$、スマホ縦画面 $< 768\text{px}$ 等）を明文化；
- **横スクロールはみ出しゼロと動的ビューポート**：`100dvh` / `100svh` を採用し、スマホ縦画面での `Horizontal Overflow <= 0px` を絶対条件化；
- **44×44pxタッチターゲットとセーフエリア退避**：すべての操作要素に $\ge 44 \times 44\text{px}$ のヒット領域と `env(safe-area-inset-*)` を強制し、`Momus-Audit` によるChrome DevTools実機サイズエミュレーション監査で検証します。
