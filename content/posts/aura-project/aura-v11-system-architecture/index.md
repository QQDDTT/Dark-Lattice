# Aura v11.0.0 核心架构：三大底座与四大自治系统

![Aura v11.0.0 核心架构可视化](featured.png)

在经历了多次迭代后，Aura 迎来了 v11.0.0 版本的重大重构（系统化架构版）。我们正式弃用了传统的层级架构与早期的对称系统模型，转向了更加纯粹、功能解耦的 **“3 大底座 (Foundations) + 4 大自治系统 (Systems)”** 架构范式。

## 1. 核心愿景：AI-Native OS

Aura 的目标并不是成为一个简单的指令响应机，而是构建一个基于 Rust 的高性能、多维度 **AI 代理操作系统 (AI-Native OS)**。
它旨在通过算法驱动的自治系统，实现**认知、执行与进化的闭环演进**。在 Aura 中，系统行为由变分自由能 (VFE) 最小化原则驱动进行自我优化。

## 2. 三大底座 (Foundations)

三大底座构成了 Aura 的坚实基础，它们分别承担着系统的逻辑基因、物理实体与控制中枢的角色：

1. **Aura Core (逻辑基座)**：
   系统的“基因”。包含全系统契约、ACP v5.0 二进制协议与核心算法集（如遗忘算法、共振模型）。它定义了全系统的数据交换标准。

2. **Aura Substrate (物理基座)**：
   系统的“物理支撑”。提供高性能的二进制存储引擎，并集成了本地模型（LLM/STT）推理后端，负责底层的向量与结构化数据持久化。

3. **Aura OS (系统内核)**：
   系统的“控制中枢”。负责系统引导、进程督导、基于 ACP 协议的消息路由与全链路安全审计。它就像是传统操作系统的 Kernel，统筹调度所有上层系统。

## 3. 四大自治系统 (Core Systems)

在底座之上，Aura 运行着四个核心的自治系统。它们通过微服务架构协作，借助 ACP 总线进行异步通信：

1. **Interaction System (交互系统)**：
   感知与唤醒。负责意图采样、**价值观模型（唤醒算法）**驱动的意图筛选，以及向用户提供全渠道的视觉与语音反馈。

2. **Inference System (推理系统)**：
   逻辑与规划。基于**世界观模型（知识获取算法）**进行因果路径演化、任务流生成与模块路由调度。它是系统的大脑，决定“要做什么”。

3. **Execution System (执行系统)**：
   物理动作落地。负责在强隔离的安全沙箱中，受控地调用已注册的物理技能。

4. **Evolution System (进化系统)**：
   评价与自我演进。基于**人生观模型（进化算法）**，负责任务执行后的效果评价、知识固化 (EWC) 以及算法参数的闭环优化。

## 4. 核心设计准则

- **算法驱动**：所有系统行为必须由 `aura-core` 定义的量化算法驱动，杜绝随意的“硬编码”行为。
- **二进制通讯**：全系统强制使用 **ACP v5.0** 二进制零拷贝协议，确保跨组件通信的高性能与低延迟。
- **因果一致性**：所有任务流必须具备可追溯的 `trace_id` 与因果时钟序列，保证执行路径的绝对可复现与可审查。
