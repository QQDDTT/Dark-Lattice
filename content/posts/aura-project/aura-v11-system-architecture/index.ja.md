# Aura v11.0.0 コアアーキテクチャ：3つの基盤と4つの自律システム

![Aura v11.0.0 コアアーキテクチャの可視化](featured.png)

複数回のイテレーションを経て、Aura はバージョン v11.0.0（体系的アーキテクチャ版）で大規模なリファクタリングを迎えました。私たちは従来の階層型アーキテクチャや初期の対称型システムモデルを正式に非推奨とし、より純粋で機能が切り離された **「3つの基盤 (Foundations) + 4つの自律システム (Systems)」** アーキテクチャパラダイムへと移行しました。

## 1. コアビジョン：AI-Native OS

Aura の目標は、単なる命令応答マシンになることではなく、Rust をベースとした高性能で多次元的な **AI エージェントオペレーティングシステム (AI-Native OS)** を構築することです。
アルゴリズム駆動の自律システムを通じて、**認知、実行、進化の閉ループ**を実現することを目指しています。Aura では、システム行動は変分自由エネルギー (VFE) 最小化原則に基づいて自己最適化されます。

## 2. 3つの基盤 (Foundations)

3つの基盤は Aura の強固な土台を形成し、それぞれシステムの論理遺伝子、物理エンティティ、制御ハブとしての役割を担います。

1. **Aura Core (論理基盤)**：
   システムの「遺伝子」。システム全体の契約、ACP v5.0 バイナリプロトコル、およびコアアルゴリズムセット（忘却アルゴリズム、共鳴モデルなど）を含みます。システム全体のデータ交換標準を定義します。

2. **Aura Substrate (物理基盤)**：
   システムの「物理的サポート」。高性能なバイナリストレージエンジンを提供し、ローカルモデル (LLM/STT) 推論バックエンドを統合して、基盤となるベクトルと構造化データの永続化を担当します。

3. **Aura OS (システムカーネル)**：
   システムの「制御ハブ」。システムのブートストラップ、プロセス監視、ACP プロトコルに基づくメッセージルーティング、および全リンクのセキュリティ監査を担当します。従来のオペレーティングシステムのカーネルのように機能し、すべての上位システムを調整します。

## 3. 4つの自律システム (Core Systems)

基盤の上で、Aura は4つのコア自律システムを実行します。これらはマイクロサービスアーキテクチャを介して連携し、ACP バスを通じて非同期に通信します。

1. **Interaction System (インタラクションシステム)**：
   知覚と覚醒。意図のサンプリング、**価値観モデル (覚醒アルゴリズム)** による意図のフィルタリング、およびユーザーに対するオムニチャネルの視覚的・音声的フィードバックの提供を担当します。

2. **Inference System (推論システム)**：
   論理と計画。**世界観モデル (知識獲得アルゴリズム)** に基づいて、因果経路の展開、タスクフローの生成、およびモジュールルーティングのスケジューリングを行います。システムの頭脳として、「何をするか」を決定します。

3. **Execution System (実行システム)**：
   物理的アクションの着地。厳密に隔離・制御されたセキュリティサンドボックス内で、登録された物理的スキルを呼び出すことを担当します。

4. **Evolution System (進化システム)**：
   評価と自己進化。**人生観モデル (進化アルゴリズム)** に基づき、タスク実行後の効果評価、知識の統合 (EWC)、およびアルゴリズムパラメータの閉ループ最適化を処理します。

## 4. コア設計原則

- **アルゴリズム駆動**: すべてのシステム動作は `aura-core` で定義された定量的アルゴリズムによって駆動されなければならず、任意の「ハードコード」された動作を排除します。
- **バイナリ通信**: システム全体で **ACP v5.0** バイナリゼロコピープロトコルを厳格に使用し、コンポーネント間通信の高性能と低遅延を確保します。
- **因果の一貫性**: すべてのタスクフローは追跡可能な `trace_id` と因果クロックシーケンスを備えていなければならず、実行経路が完全に再現可能で監査可能であることを保証します。
