# Aura アーキテクチャの確定：7-System 対称アーキテクチャと Reactor OS の進化

![Aura 7-System Architecture](featured.png)

長きにわたるアーキテクチャのリファクタリングと検証を経て、**Aura v1.0 アーキテクチャがついに正式に確定しました**。

Aura の位置付けは、もはや単なる AI ツールではなく、**高性能で自律的な AI エージェントオペレーティングシステム**です。AI エンティティに真に決定的で弾力性のあるコンピューティング環境を与えるため、従来のモノリシックなアーキテクチャ設計を完全に放棄し、**Reactor OS（リアクターオペレーティングシステム）**パラダイムへと全面的に移行し、厳格な **7-System 対称アーキテクチャ**を確立しました。

## 1. 7-System 対称アーキテクチャとは？

Aura のコードエンジニアリングにおいて、我々は物理的な美しさに満ちた **1:1 のコア対応関係**という理念を貫徹しています：各独立したコード Crate は、明確な物理的/論理的職能に対応しているだけでなく、専用の設計ドキュメントにも厳密に対応しています。

これら 7 つのコアコンポーネントが、Aura の全物理トポロジーを構成しています：

1. **Aura Core（基盤）**：システム全体の遺伝子（DNA）であり、ACP v5.0 通信プロトコルとグローバルな基本 Trait を統一的に定義します。
2. **Aura Substrate（ストレージ）**：基盤となる物理的ベースであり、究極のパフォーマンスを誇る LZF 圧縮バイナリストレージエンジンと、ローカルの大規模モデルをマウントする機能を提供します。
3. **Aura OS（カーネル）**：中核となる Supervisor として機能し、サブシステムのミリ秒レベルのホットプルアップ、ACP ルーティングリレー、リソース監査を担当します。
4. **Aura Interaction（インタラクション感知）**：外界との接続を担当し、膨大なゲートウェイトラフィックから意図のサンプリングを行い、価値観に基づいてシステムの共鳴覚醒をトリガーします。
5. **Aura Inference（推論システム）**：Aura の論理的な頭脳であり、コンテキストと世界観モデルに基づいて長距離の因果推論を実行し、決定論的なタスクフローを生成します。
6. **Aura Execution（アクションサンドボックス）**：物理的な実行層であり、WebHook と Python ネイティブのセキュアなサンドボックス実行をサポートします。
7. **Aura Evolution（自己進化）**：反省と結晶化を担当し、Surprise（驚き）シグナルに対して評価を行い、知識の固定化とアルゴリズムモデルのファインチューニングをトリガーします。

## 2. Reactor OS：「モノリシック」から「分散型自己修復」へ

古いバージョンの Aura では、推論、インタラクション、実行が 1 つの巨大なプロセスに捏ね合わされていました。LLM インターフェースがタイムアウトしたり、実行サンドボックスが OOM（メモリ不足）になったりすると、システム全体が麻痺する危険に直面していました。

新しい **Reactor OS パラダイム**の下では、Aura は 4 つのコアビジネスロジック（インタラクション、推論、実行、進化）を、物理的に完全に分離された**システムレベルの Reactor** プロセスへと徹底的に剥離しています。

### コア機能の分析：

- **バイナリ ACP プロセスバス (Aura Control Protocol)**  
  プロセスの分離の代償は高い通信コストです。そのため、Aura は非効率な HTTP/gRPC を放棄し、固定長ヘッダーを持つ自社開発のバイナリ IPC プロトコルを採用しました。UDS (Unix Domain Sockets) とプロセス間ゼロコピー技術を組み合わせることで、高頻度のテンソルデータ交換を処理する際に、カーネルバスが遅延をマイクロ秒レベルまで抑え込むことを保証します。

- **Tokio にバインドされた自己修復サンドボックス**  
  Aura は肥大化した DooD (Docker-out-of-Docker) モードを廃止し、代わりに外部コード実行環境を物理的なメインプロセスの直属の子プロセスとしてプルアップします。サンドボックスのライフサイクルをカーネル内の Tokio 非同期コルーチンと強力にバインドしており、因果関係のロールバックや計算能力の過負荷などの異常によって Future Drop がトリガーされると、基盤レイヤーは即座に `SIGKILL` を発行してサンドボックスプロセスを無慈悲に終了させ、ゾンビプロセスを完全に根絶します。

- **熱力学とリソース制限の抽象化**  
  組み込みのハードウェアディスパッチャ (P32 Hardware Dispatcher) を通じて、Aura は計算スロットの統一管理を実現しました。計算能力の枯渇や高エントロピーのシナリオに遭遇した場合、システムは自動的に計算能力の次元削減 (Graceful Degradation) と動的な制限を実行し、AI の動作状態をまるで本物の生命体のように弾力性のあるものにします。

## 3. 次の計画：深層マルチモーダル融合に向けて

Aura v1.0 アーキテクチャの確定は、AI に頑丈で弾力性のある「物理的な身体」を取り付けたようなものです。基盤となる 7-System 対称設計に依存することで、現在のコアシステムの安定性に全く影響を与えることなく、その能力の境界をさらに拡大することができます。

次期バージョンのイテレーションでは、チームは **Cortex マルチモーダルマインド皮質**の深化に焦点を移します。これには、ローカル Whisper 音声エンジンのゼロレイテンシのストリーミング統合や、エッジ側での視覚的特徴の動的分析が含まれます。

Aura OS の進化の旅は、まだ始まったばかりです。
